# 存储成本与正式接入方案

## 当前可运行实现

原生微信小程序（微信登录） / 浏览器（本地演示登录） → Node HTTP API → SQLite；视频流式落盘 → FFprobe 真实校验 → FFmpeg 单份转码/截帧 → 原子提交作品和次数账本。支付目前关闭，已有额外次数与每日免费次数保留。

同一用户最多一个正在处理的上传，全局最多两个，同时限制上传体积、时长与处理超时。视频不进入数据库、不转 Base64，也不会把整份文件读入业务内存。数据库事务只包裹短时元数据操作，不占用整个转码过程。

本地播放由后端签发 15 分钟短链，每次访问重新检查作品状态和权限。支持 `Range` 和 `HEAD`。签名密钥当前仅在进程内，重启后旧链接失效，刷新页面可获取新链接。短链属于持有者凭证，过期前可以被转发；不能承诺 DRM 或阻止已授权用户保存/分享内容。

## 为什么先只保留单份压缩视频

大量观看的成本通常由下行流量而非存储决定。对不超过 90 秒的手机舞蹈短片，先使用一份 H.264 MP4 可以减少多档转码、HLS 小分片请求和重复存储。首屏只请求封面，播放器在用户打开详情后才加载视频，采用 `preload=none`，不在信息流自动播放。

当前设定更偏低成本：转码边界框为 720×1280，横屏片也会限制宽度到 720。视频 CRF 26，最大目标码率 1.2Mbps，音频 64kbps。实际清晰度需要用真实舞蹈动作验收，快速旋转、灯光噪点可能需要调高码率；不要在画质未经确认时批量不可逆删除用户的重要原片。

客户端标题绘制不增加每次图片处理费用；仅一次截帧和平均色计算。若要求所有设备完全一致的书法字形及可独立分享的带字封面，可后续使用有授权的字体在转码工序中生成最终带字 JPEG。

## 预算计算方法

以下是容量推算，不是云厂商报价：

`单次完整观看 MB ≈ (视频 Mbps + 音频 Mbps) × 秒数 ÷ 8`

按平均合计 1.264Mbps、90 秒完整播放估算，每条约 **14.22MB**；1 万条约 142GB；10 万次完整播放约 1.42TB 下行。实际 CRF 编码可能低于此值，容器开销、重复请求、观看完成率会改变消耗。

月费用估算应拆为：

`存储 GB × 存储单价 + 用户下行 GB × 下行单价 + 回源 GB × 回源单价 + 请求量费用 + 转码费用 + 应用/数据库/备份费用`

不要仅比较存储每 GB 单价。腾讯云 COS 开启 CDN 后仍有 COS 回源流量计费；数据万象媒体处理也单独按使用量计费，具体取决于采购渠道与计费产品。

## 正式部署建议（尚未接入）

首期可用小规格应用服务 + **私有 COS 标准存储桶**，只保留压缩版与封面。少量、低频观看先比较对象存储直接短链的总费用；当观看量、缓存命中率或体验需求上升，再比较 CDN / EdgeOne 的总成本。低延迟作为第二目标，不预先购买大额带宽包。

1. 对象存储必须私有。应用数据库的“公有”表示可被所有登录用户发现，不代表把存储桶设成公开读。签名链接只在权限校验后下发，待审与私有内容不进入公共缓存。
2. 申请受限直传凭证/预签名上传 URL，按用户分配随机对象 key、大小限制与有效期。完成回调只把上传标为接收，异步任务验证真实文件，再转码；客户端声称上传成功不能直接上架。
3. 对象存储无法与 SQLite 事务原子提交。正式直传需新增上传预留、完成、失败状态与幂等键；免费/付费额度原子预占，超时释放，成功提交才最终扣次。定时清理中断原片、失败产物和无人引用对象。
4. 低访问素材能否转低频存储取决于最低存储时长与取回费用。需要立即播放的素材不直接使用归档层。先观察访问热度再配置生命周期。
5. 做数据库与媒体备份、账本核对、异常流量告警及出流量预算。审核日志保留操作者、状态、原因和时间。

## 微信身份与支付接入

AppID 已配置，AppSecret 仅保存在被版本控制忽略的服务端 `.env`。已实现 `wx.login` 的 code 由服务端通过官方 code2Session 接口换取身份，不接受客户端传入角色/openid。新用户默认为学员，老师/管理员由本地运维脚本授权；真实登录尚需微信开发者工具/真机验收。合法 HTTPS 域名与上线部署仍待配置。

上传次数属于数字服务，上线前应按当时微信平台的商品类目、终端与支付政策确认适用支付产品，不能假定普通实物商品 JSAPI 支付通道在所有场景都可用。本版本未连接商户，未实现真实收款、退款或提现。

接入确认后的微信支付产品时：

- 金额由服务端用整数分计算；保存商户订单号、购买次数与所属用户。
- 客户端支付成功只用于显示“等待到账”，不能直接增加次数。
- 服务端验证通知签名、解密资源、检查商户/AppID/订单号/金额/币种/付款状态，在数据库事务内唯一记账。
- 重复通知返回相同结果；通知丢失通过主动查单补偿，待付款订单支持恢复查询。
- 证书、商户私钥与 API v3 密钥只存放在服务端密钥配置中，不进入小程序包。

官方参考：[小程序支付接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)、[支付通知的验签要求（合作伙伴文档）](https://pay.wechatpay.cn/doc/v3/partner/4012886152)。实际商户接入应选择对应直连/服务商及获准商品类型的文档。

## 当前边界

- `APP_MODE=demo` 的浏览器演示可切换管理员，仅适用于本机联调。实际用户环境使用 `APP_MODE=wechat` 关闭演示登录，旧演示登录态也会失效。
- 已实现管理员分类管理及带视频分类的转移删除。微信用户的角色授权通过本地运维脚本完成，尚无在线用户管理界面。
- 人工审核已实现，未接入平台机器内容审核；作品与标签没有编辑/删除功能。
- SQLite 单进程 + 本地磁盘适合联调，未实现多节点任务队列、持久上传任务恢复和云直传。
- 列表当前在应用侧过滤，适合小数据量；正式大数据量需 SQL 分页、规范化标签表与检索索引。
- 自动化测试使用合成视频；真实舞蹈压缩效果、微信工具编译与真机体验需验收。
